# Stitch 医疗助手高保真前端设计

## 目标

在当前项目目录中建立一个可本地运行的 React 单页应用，严格复刻 Stitch 项目“PRD Based UI Prototypes”的 5 个业务页面，并以已拉取的 Design System 与页面内资源为视觉基准。

## 范围

包含以下页面：

1. 首页 - 康伴智能医疗助手 (Redesigned)
2. 健康趋势 - 康伴智能医疗助手
3. AI 智能问诊 - 康伴智能医疗助手
4. 病历管理 - 康伴智能医疗助手
5. 用药管理 - 康伴智能医疗助手 (含时间轴)

Design System 作为全局 token、组件和视觉规则来源，不单独作为业务路由。

## 方案

采用 React + Vite 单页应用。使用 URL hash 表示当前页面，避免引入后端或复杂路由依赖；左侧导航在桌面端固定显示，在移动端折叠为顶部菜单。页面状态使用本地 React state，仅实现原型中可见的交互反馈。

## 视觉基准

- 画布使用浅紫灰/近白背景，内容区域使用白色卡片。
- 主操作色使用 Design System 的朱红色 `#E63946`，辅助结构色使用深蓝色。
- 标题使用 Plus Jakarta Sans，正文与数据使用 Inter。
- 卡片采用柔和圆角、轻量阴影和清晰层级；交互控件满足至少 48px 触控尺寸。
- 图标使用 Material Symbols，不以 emoji 或手绘 SVG 替代。
- 使用 `stitch-prd-ui-prototypes/assets` 中的本地图片，并保留页面截图作为视觉验收基准。

## 页面结构

### 首页

左侧导航、问候语、AI 智能问诊主 CTA、健康指标卡、设备卡、右侧个人信息/用药提醒/近期报告。主 CTA、指标卡和侧栏项目具有 hover/active 反馈。

### 健康趋势

顶部搜索与工具入口、健康趋势折线图区域、个人资料卡、近期记录列表、血压/血糖/体重摘要卡。时间范围和指标卡可切换选中态。

### AI 智能问诊

左侧导航、患者信息卡、健康概览卡、问诊对话区和底部输入栏。输入内容可以发送为新的用户气泡，助手区域显示模拟回复或建议状态。

### 病历管理

上传记录卡、近期文件列表、文档预览区域、AI 分析摘要、关键健康数据卡和底部病历时间轴。点击文件项更新预览选中态。

### 用药管理

页面标题与操作按钮、相互作用警告、今日用药时间轴、当前用药方案列表、检查相互作用卡和月剂量统计卡。筛选按钮和方案卡支持可见选中/展开反馈。

## 共用组件

- `AppShell`：侧栏、顶部栏、页面画布与移动端菜单。
- `Sidebar`：页面导航、底部帮助/退出入口、当前页面状态。
- `TopBar`：搜索、通知、用户入口和页面级操作。
- `Card`：统一表面、边框、圆角、阴影和间距。
- `StatusChip`、`MetricCard`、`Button`、`IconButton`、`Input`。
- `PatientCard`、`FileList`、`ChatMessage`、`Timeline`、`ChartCard`。

组件只抽象跨页面重复且视觉规则一致的部分；页面特有布局保留在页面模块内，避免为了未来扩展增加无用抽象。

## 数据与交互

使用本地静态数据驱动页面展示。以下交互必须可用：导航切换、移动端菜单开关、问诊消息发送、病历文件选择、指标/筛选选中、用药方案展开。不会实现真实账号、后端存储、医疗诊断或 API 请求。

## 响应式

桌面端以 Stitch 截图尺寸为主要验收基准；移动端以 390px 宽度验证。移动端将侧栏收起、内容改为单列，保留主要 CTA 和核心数据，不允许水平滚动或主要控件出屏。

## 验收标准

- 本地开发命令可以启动页面。
- 5 个页面均可通过侧栏切换，并与对应 Stitch 截图保持结构、比例、颜色、间距和信息层级一致。
- 页面内图片均引用本地资产；核心交互有明确视觉反馈。
- 390px 移动视口无水平溢出，菜单、CTA 和核心内容可操作。
- 浏览器控制台无阻断性错误。
