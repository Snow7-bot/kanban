# 康伴 Agent 多轮记忆边界

第六个优化任务为“多轮记忆与上下文管理”。当前实现复用既有 `chat_sessions` 和
`chat_messages`，不新增独立记忆库，也不把患者数据库快照当作长期聊天记忆。

## 当前轮编排

1. 服务端先校验会话所属账号、当前患者和家庭 `USE_AI` 权限。
2. 只从当前 `sessionId` 读取历史，且只允许 `user`、`assistant` 消息。
3. 排除当前待处理的用户消息，避免本轮问题重复注入。
4. Agent 按消息数量、估算 Token 数和单条字符数裁剪较旧内容。
5. 当前患者数据库快照与 RAG 证据只作为本轮上下文；工具返回只存在本轮工具循环中，
   仅保存安全的工具轨迹摘要，不把工具正文写入下一轮历史。

## 默认边界

| 配置 | 默认值 | 作用 |
| --- | ---: | --- |
| `APP_AGENT_MAX_HISTORY_MESSAGES` | 12 | 最多发送的历史消息数 |
| `APP_AGENT_MAX_HISTORY_TOKENS` | 6000 | 历史消息估算 Token 上限 |
| `APP_AGENT_MAX_HISTORY_MESSAGE_CHARACTERS` | 4000 | 单条历史消息字符上限 |

生产环境可通过环境变量调整，但不建议无限增大；医疗数据越多，越应优先使用受控工具和
RAG 证据，而不是把完整历史全部发送给模型。

## 隔离原则

- 不同患者必须使用不同的 `memberId` 会话；切换患者时由服务端创建或恢复对应会话。
- 共享家庭账号的历史仍以会话权限校验为前提，客户端不能通过传入历史或患者 ID 绕过权限。
- 工具结果、患者快照和知识库正文不写入 `chat_messages.content` 作为长期记忆。
- 历史裁剪从较旧消息开始，保留最近一组对话，避免截断在当前轮中间。
